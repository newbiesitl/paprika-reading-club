# Literature reviews

Start with a question and intended decision. Give the Literature Reviewer seed papers or shared posts, a date range, available time, and the desired review depth. For example:

> Review how learned world models support planning beyond imitation. Start with MuZero and DreamerV3, include contrary evidence, and produce a rapid review with an evidence table and source links.

Create one directory per authorized review, using a descriptive question slug. A typical review contains:

- `scope.md`: question, review type, criteria, permitted sources, date range, and limitations.
- `search-log.md`: sources, exact queries, search dates, result counts, duplicate handling, and screening decisions with exclusion reasons.
- `evidence.md`: included studies, stable identifiers, inspected versions, access level, design, outcomes, uncertainty, limitations, and evidence locations.
- `synthesis.md`: themes, disagreements, calibrated conclusions, gaps, and the decision the evidence informs.
- `references.bib` or a bibliography in the synthesis: verified metadata and source links.

Use Paprika Inc’s project-local paper lookup, literature review, citation management, and scientific critical thinking procedures, with each skill’s portability guidance. A rapid or narrative review need not claim systematic coverage. A systematic review requires the corresponding methods and screening evidence; a meta-analysis also requires suitable data and a justified statistical plan.

The [ownership map](../company/ownership.json) defines responsibility and independent review. Record the precise candidate reviewed and unresolved limitations. Human review can be used when peer communication has not been authorized. Scholarly access and optional integrations must be checked when needed; installation alone does not verify them.
